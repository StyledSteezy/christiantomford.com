How CountSift works

CountSift compares what an IT provider bills against the devices and licenses it actually manages. This is how it reads the exports, matches names that each system spells differently, finds the counts that disagree and prices each gap, all inside the browser.

01The problem

Three exports, three ways of counting

Billing and reality drift apart

A managed IT provider (an MSP) bills each client from its PSA, the system that holds its contracts and invoices: so many managed workstations, servers and Microsoft 365 seats, each at a monthly rate. What it actually manages is recorded somewhere else. The RMM agent lists every device that checks in, and Microsoft’s license report lists every seat.

When the counts drift apart, the provider is managing devices and licenses it doesn’t bill for. Checking means lining up exports that were never designed to be compared. Here is one client in three of them. All three go into a single drop zone, and CountSift works out from their columns that the first is the billing export and the other two are sources of truth.

Four differences at once

  • Column names. The client is in Company Name, Organization or Customer, depending on the file.
  • Client names. Halsted & Grant LLP in billing is Halsted and Grant everywhere else.
  • Product names. Billing says Managed Workstation; the RMM says Workstation.
  • Shape. Billing has a quantity on each line. The RMM has a row per device, so the count has to be built from the rows.

CountSift has to get past all four before it can say, for each client and product, what is billed, what is actually there, and what the difference is worth.

02From CSV files to a comparison

The pipeline, and the diagram that shows it

  1. ReadEach CSV is parsed in the page into a header row and data rows, then sorted as the billing export or a source.
  2. MapColumns are assigned to Customer, Item, Quantity, Monthly rate and Last contact, guessed from the headers.
  3. CleanNames become comparison keys, so case, punctuation and endings like LLC stop mattering.
  4. MatchClients are paired across files, then products within each client, exactly or by similarity.
  5. CompareBilled quantity is set against counted quantity, and each difference is priced at the monthly rate.

A diagram drawn from the real settings

The diagram isn’t an illustration of the pipeline in general. It’s generated as SVG from the same state the comparison runs on: which column each file uses for each field, whether the 30-day device filter is on, and whether matching is fuzzy or exact and how strict. Change any of them and it redraws. The clean-up step even shows a real pair of names from the loaded files that become the same key, such as Acme Corp and Acme Corporation.

  • Quantity and rate columns run to the comparison on their own horizontal lanes, and the boxes in the middle are laid out around those lanes, so no line crosses a box.
  • Each line carries the ids of everything on its path. Hovering a column, step or comparison row highlights its whole route, and clicking a column jumps to its picker.
  • Screen readers get an aria-label written from the same data, file by file and column by column.

03Reading the files

CSV parsing, file roles, column mapping, guardrails

Parsing

Files are parsed with Papa Parse, loaded from a CDN. If that script can’t load, for example offline or on a locked-down office network, a small built-in RFC 4180 parser takes over. It handles quoted fields, doubled quotes and line breaks inside quotes, guesses the delimiter (comma, semicolon, tab or pipe) from the header line, and drops the byte-order mark Excel adds. The page footer says when the fallback is in use.

Numbers are read the way exports write them: 1,250, $25.00 and the accounting-style (3) all parse.

Guessing the columns

Each field has a ranked list of header names that usually mean it. A header that equals a candidate scores higher than one that only contains it, earlier candidates win ties, and each column can be used only once. On the test exports this maps Company Name to Customer, Product to Item, Qty to Quantity and Unit Price to Monthly rate without any help. The guess is shown over a preview of each file, and every choice can be changed.

Only Customer is required. Two defaults let device lists work without reshaping them:

  • With no Quantity column mapped, each row counts as one, which is right for an RMM export where every row is a device.
  • With Item mapped to the device type, Halsted & Grant’s 31 device rows become two counts, workstations and servers.

Telling the files apart

All the exports go into one drop zone, so CountSift first works out which file is the billing export. It runs the same column guesser on each file and checks the values under what it finds: a price column of numbers next to a quantity suggests the billing export, device names with a last-contact date suggest a device list, and Licenses or Seats columns a license report. Prices alone don’t decide it: a vendor invoice from a distributor like Pax8 has them too, and its supplier columns, such as SKU or Term, count against it. Each file shows the role it was given and why, an unsure guess is marked, and one click switches a role. When no file looks like a billing export, or more than one does, CountSift asks instead of picking.

Guarding against bad input

  • The same file twice. CountSift fingerprints each file’s text with an FNV-1a hash and skips an identical file with a notice. A second file with the same name, columns and row count is skipped too.
  • Values that aren’t numbers. A quantity like n/a marks its line Couldn’t compare instead of counting as 0, which would create a gap that isn’t there. Rows with no client name are skipped. Both are listed above the results, once per file.
  • Devices that have gone quiet. When a device list has a Last contact column, devices not seen in the 30 days before the newest check-in in that file are left out (on by default, and reported). It counts back from the newest date in the file rather than today, so an export pulled a month ago isn’t emptied for being old. In the test RMM export, that sets aside four devices, two of them Halsted & Grant workstations last seen in July and August.

04Matching names

Normalization, then fuzzy matching

Clean by rule first

Every client and product name becomes a key before anything is compared. The key is lower-cased, & is read as “and”, periods are dropped (so L.L.C. becomes llc), any other character that isn’t a plain letter or digit becomes a space, and common abbreviations are expanded: M365 to Microsoft 365, Svr to Server, Sq to Square, St to Street. Client names also lose a leading “The” and trailing words like Inc, LLC, Corp, Co, Group or Agency, as long as one word is left.

These differences are predictable, so rules handle them, and the rules apply in both matching modes. That leaves the similarity score for what rules can’t catch: typos, spacing and extra words.

Then score what’s left

In fuzzy mode, names that still differ are compared word by word. Each word of the shorter name is paired with its closest unused word in the longer one. An identical word scores 1; otherwise the score is the Dice coefficient of the two words’ letter pairs, so a typo still scores high. Words scoring under 0.5 count as 0, and the name’s score is the average over the shorter name’s words.

Because the shorter name drives the score, an extra word costs nothing: Workstation is fully contained in Managed Workstation. A different word does cost something, which is what keeps plan tiers apart: Standard and Premium share no letter pairs.

Pairing is one-to-one. Exact key matches pair first. Every remaining pair at or above the strictness threshold becomes a candidate, and candidates are taken highest score first, each name used once. Clients are matched across files first, then products within each matched client.

Strictness is a trade-off

The threshold is a slider from 0.50 to 1.00 under Advanced matching, set to 0.80 by default. On the test exports (billing, RMM, license and backup reports), moving it changes the answer in both directions:

StrictnessMissed revenue per monthWhat changes
0.65$448.00Business Standard now “matches” Business Premium, so a client billed for the cheaper plan while using the more expensive one is no longer flagged.

Exact mode turns fuzzy pairing off. On the same files it finds 11 clients instead of 9 and 14 billed lines it can’t find in any source, because, for example, Managed Workstation and Workstation are different strings, and so are Ravenswood Architects and Ravenswood Architecture.

05Comparing and pricing

Discrepancies and their monthly impact

Aggregate, then compare

Each file is reduced to client → product → quantity by summing its rows. When several rows bill the same product at different prices, the rate is their quantity-weighted average. Source files are merged. If two of them count the same client and product, CountSift uses the higher count rather than adding them, and marks the line Sources disagree when the counts differ.

Every billed line and every unbilled source item then gets one status:

Under-billed
The source counts more than is billed. This includes products, and whole clients, with no billing line.
Over-billed
More is billed than the source counts.
Plan mismatch
Billed for one plan while the source shows another plan of the same product, in the same quantity.
Matched
The counts agree.
Not in source
A billed line with no counterpart in a file that covers that kind of product. It’s listed for review and left out of the dollar totals.
Not checked
A billed line for a product no source file covers, like Cloud Backup with no backup report loaded. A missing match there says nothing about the client, only about the files, so the line isn’t counted against them. The report suggests which export would check it.
Couldn’t compare
A quantity on either side isn’t a number.

Plan mismatches

A client billed for one Microsoft 365 plan while using another would otherwise show up as two unrelated problems: a billed line that isn’t in the source, and an unbilled product. CountSift pairs them into one finding when, within a client, the two names share at least their first two words and the quantities are equal. Business Standard and Business Premium share three words (“microsoft 365 business”). Managed Workstation and Managed Server share one, so they stay separate products.

Where the prices come from

Dollar figures use the billing export’s monthly rate: the difference times the rate, and that times 12 for the year. An unbilled product has no billing line to take a rate from, so CountSift borrows one, in this order:

  1. The rate billed for exactly the same product, after clean-up, at other clients (the most common one, if they differ).
  2. Otherwise, the rate of the billing line that this source item was matched to at other clients. Wicker Park Yoga appears in the RMM and license report but isn’t billed at all. Its three RMM workstations are priced at $35.00, the Managed Workstation rate that the RMM’s “Workstation” matched at other clients.

It never borrows from a product that only looks similar. In the built-in sample, no one is billed for Business Basic, so a client’s 10 unbilled Business Basic seats are listed with no rate and counted separately, not priced at Business Premium’s $22.00. Borrowed rates are marked est. in the table, and the summary says how much of the total depends on them. On the test exports that’s $562.00 a month, including $283.00 at estimated rates.

Totals that don’t hide anything

A client can be under-billed on one line and over-billed on another. The client’s row shows both figures stacked, never one net number (Northshore Pediatrics: +$8.00 under, −$35.00 over), so money the provider is owed doesn’t disappear behind a credit it may owe back. Quantities aren’t totalled per client at all, because workstations plus license seats isn’t a meaningful number. And with no price column mapped, the revenue figure reads “—” with a prompt to map one, not $0.00.

06Running in the browser

Architecture and trade-offs

No backend

The page reads each file with the browser’s File API, and parsing, matching and the comparison all run in that tab. The CSV report is built in the page and downloaded as a Blob, and printing uses the browser’s own print. There are no accounts, no cookies and nothing saved in the browser. Billing exports carry client names and prices; with no server there is nothing to upload, store or secure, and the privacy page can say so plainly. The only library is Papa Parse.

Analytics needed one workaround. Cloudflare Web Analytics, which Cloudflare adds to the page, counts page views. To count finished comparisons the app changes the address to a fixed /results (or /sample) with the History API when results appear. Nothing from the files ever goes into the URL, and a refresh on either path loads the app from the start.

One file, with the engine kept apart

The application is one JavaScript file with no build step (plus a small file of embedded sample data), in numbered sections: state, utilities, CSV parsing, column detection, the matching engine, views, report export and wiring. The comparison itself never touches the page. One function, computeResults(), runs a whole comparison from the loaded files and settings and returns rows, client groups, a summary and notes for the views to render. The progress animation shown during a run calls the same function, so its checklist shows the comparison’s real counts rather than placeholder steps.

It ships as a static site on Cloudflare Pages. After a browser once ran a cached older app.js against a newer page and broke on load, the site’s own CSS and JS URLs got a version tag taken from a hash of each file. A small script stamps the tags whenever those files change, and the tests fail if one is out of date.

Testing

An end-to-end suite drives the real page in headless Chromium with Playwright. It runs the sample and the test exports and checks their totals and specific lines against expected results documented with the test data, such as Lincoln Sq Insurance matching Lincoln Square Insurance Agency and Ravenswood showing as a single $114 plan mismatch. It also covers how each test file is sorted, each guardrail above, the mapping diagram and layouts at phone widths, and it runs the whole flow on the built-in fallback parser.

Trade-offs and limits

  • Nothing persists. Column mappings aren’t remembered between visits yet, and with no server a reconciliation can’t run on its own each month.
  • Matching is one-to-one. There’s no way yet to say that several source items count toward one billing line, such as Laptop and Desktop toward Managed Workstation.
  • The rules live in code. The abbreviation list and the list of trailing company words are fixed, so a provider’s own shorthand has to be added there.
  • CSV only. Excel workbooks have to be saved as CSV first.
